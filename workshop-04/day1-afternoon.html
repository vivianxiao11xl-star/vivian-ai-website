从 Context 到 Skill V0
把判断变成可复用的 AI 员工

上午完成第一次 Agent 交付；下午把一次性的结果继续沉淀成文件、Context、3C 任务简报与 Skill V0，再为晚间 AI 员工发布会完成组队和任务定义。

Day 1 · 下午 Context 管理 3C → Skill V0 AI 员工共创
“聊天中的结果会消失；写进文件、能被再次调用的方法，才会产生复利。”
下午完整闭环：状态切换 → 网站验收 → 看见复利 → Context 管理 → 3C 任务简报 → Skill V0 试跑与人工验收 → 四条赛道共创 AI 员工。
One-page takeaway

下午最值得带走的三个判断

01 · Context

不是越多越好，而是越准越好

资料库像图书馆，窗口像这次工作的书桌。每个任务只带真正相关的文件，才能减少污染和误判。

02 · Skill

复制的不是动作，而是判断

模板能给出通用答案；真正值钱的是顶尖员工对资料、步骤、例外、停止条件与验收标准的判断。

03 · V0

第一版要跑起来，再持续写回

Skill V0 不是终点。自己试跑、让同事使用、人工验收，再把失败点和反馈写回去，才会越来越稳。

Live sequence

现场是怎样一步步推进的

1. 先恢复人的状态

一段简短的呼吸、觉察与拉伸练习，让大家从高强度上午切换回来。未来可以把更多执行交给 AI，但人的注意力与判断力仍是系统上限。

2. 验收网站：Context 有没有真正被看见

大家比较不同业务的网站结果：生活与投资、食品品牌、制造业、医疗创新、家具项目。重点不是统一模板，而是事实、行业气质和本人审美是否进入作品。

3. 看见午间复利

同一段休息时间里，AI 并行完成课堂作品展、当日笔记网站和公众号草稿。速度来自旧模板、流程与 Skill 已经沉淀，而不是每次从零解释。

4. 认识 Skill 与人机关系五阶段

从黑盒、实习生、队友、项目管理者到合伙人，升级靠的不是一句神奇 Prompt，而是 Context、方法、标准、权限和反馈系统。

5. 主动管理 Context

一个任务一个窗口；长任务先做交接；多对象研究拆成独立上下文；通过相对路径只引用当前真正需要的文件。

6. 用 3C 生成 Skill V0

选择真实场景，让 AI 逐题采访，先生成 TASK-BRIEF.md，经本人确认后再形成 Skill V0，并在现场试跑、展示与验收。

7. 整理文件系统，进入晚间共创

根目录启动文件、业务线、README 索引、过程稿与最终版被重新梳理；随后按财务、项目管理、内容和销售四个方向组队。

Compounding demo

午间半小时，为什么能同时长出三项产出

作品展

全班网站进入同一入口

链接被整理成可浏览的作品展，并加入扫码、大屏放映和遗漏项追踪，方便现场展示与后续补齐。

笔记网站

沿用成熟结构，只更新本期内容

上一期已经验证过的页面结构直接复用，新一期开场前就准备好骨架，课堂结束后马上填入新内容。

公众号草稿

录入新语料，沿用旧流程

把现场表达、核心角度和作品图片交给既有写作流程，生成可审核的草稿，再由本人做最终判断。

真正的复利：第二次不再从空白开始。新任务只补充本期变量，已经验证过的结构、步骤、标准和发布动作继续复用。
Context management

资料库是图书馆，窗口是这次工作的书桌

一个任务一个窗口

不要把网站、研究和内容混在一起

任务切换就开新窗口，减少历史指令、旧版本和无关资料互相污染。

长任务做交接

对话变脏时，先总结再重开

让 AI 输出阶段总结或交接文档，再把干净上下文带入新窗口继续。

大任务先拆后合

独立研究，再统一汇总

多家公司、多对象任务分别使用独立上下文，避免越往后越敷衍。

精准引用文件

只带当前真正需要的资料

通过相对路径引用指定文章、项目或数据；不相关的 Context 及时移除。

From 3C to V0

把模糊需求，变成可以上岗的第一版 Skill

Context

为谁做、为什么做、看什么

明确对象、目标、业务背景、必读资料与当前约束，让 AI 不必凭空猜测。

Components

经过哪些步骤、交付什么

拆出模块、顺序、工具、人审点和最终交付物，把一团想法变成可执行流程。

Criteria

什么算好、何时必须停

写清格式、质量标准、禁止事项、停止条件与转人工边界，让验收不再靠感觉。

选择一个真实任务

从自己明天还会发生的工作出发，而不是做一个泛泛的演示。

AI 逐题采访，生成 TASK-BRIEF.md

人负责提供业务事实和判断；AI 负责追问、结构化并留下可确认的任务简报。

本人确认后，生成 Skill V0

先锁定目标、输入、步骤、输出、标准和边界，再让 AI 写成可重复调用的员工手册。

试跑、验收、写回

自己用、交给同事用；结果不稳定，就继续补资料、补标准、补停止条件。

Learner outputs

同一个框架，长出四种完全不同的 Skill V0

任务采访官

先问清，再决定写到哪里

读取 USER 与历史资料，先把初稿放进收件箱；信息冲突多轮仍无法判断时停止，交给本人确认。

品牌内容生产

读取品牌 Context，不擅自发布

结合产品、受众和既有表达生成内容，先提供本人或团队审核版本，再决定是否进入发布环节。

课程感悟转内容

录入事实、感悟与真实素材

把课程内容、本人感受和现场图片组合起来，输出图文、电子杂志等不同阅读版本。

月度销售分析

先锁定数据，再稳定输出

明确 ERP 等输入，固定总览、客户、项目、销售流向、回款、在谈机会和下月行动结构。

为什么结果不同：大家使用的是同一套 3C 方法，但真正决定 Skill 价值的，是每个人写进去的业务事实、经验、审美和判断。
Knowledge system

文件系统不是仓库，而是 AI 的工作地图

根目录放启动文件

用 USER.md 等文件说明“我是谁、我做什么、我怎样判断”，让新窗口先读到稳定身份。

按业务线组织高频工作

把内容、客户、学习、财务等业务分区，而不是把所有资料塞进一个大文件夹。

每个项目建立 README／索引

像地图一样说明目录里有什么、从哪里开始读、重要交付物在哪里。

过程稿与最终版分开

AI 可以生成很多版本，但只有经过本人判断的那一版，才进入最终版并对外使用。

定期让 AI 整理，而不是越生成越乱

每周或每两周检查命名、归档和索引，同时确保 PDF、Excel、PPT 等真实业务文件都可见。

Information to asset

Web Clipper 与定时情报：把看过变成可复用

网页进入本地

保存原文，再做双语与深度加工

文章、论文和网页先进入 Obsidian，保留来源；随后生成中英对照，并在研究、写作和分享时继续引用。

重复情报自动运行

固定信源、规则、结构与时间

AI 创作者动态、专业行业信息、VC 与科技简报都可以定时扫描，并进一步生成网页或音频版本。

Vivian's judgments

下午的七句总控

重复工作

“电脑上需要做第二次的事情，都值得考虑做成一个 Skill。”

不要只解决这一次，要留下下一次能直接调用的方法。

真正壁垒

“模型可以买到，私有 Context 买不到。”

业务资料、审美、判断和历史反馈，才会让通用模型变成你的 AI 员工。

上下文

“不是越多越好，而是越准越好。”

每次工作只装载真正相关的信息。

最佳实践

“顶级员工难复制，顶级方法可以复制。”

Skill 最值得保存的是高手的例外处理与验收判断。

管理方式

“AI 不需要情绪价值，但需要清晰管理。”

目标、信息、权限、标准与停止条件要给全。

记忆

“AI 天生没有记忆，文件才是人为给它的记忆。”

长对话结束后，把结论和做法主动写回 MD。

持续迭代

“V0 不是完成版。”

试跑、验收、同事使用、反馈写回，才会形成稳定资产。

四条赛道，开始共创真正的 AI 员工

下午收尾时，大家按财务、项目管理、内容生产和销售四个真实业务方向组队。每组先锁定共同场景，再为 AI 员工定义名字、Slogan、服务对象、岗位职责、上岗材料、人机边界与交付物。

Finance

财务

Project

项目管理

进度、跨部门协作、会议执行或质量检查。

Content

内容生产

选题、调研、生产、分发与多载体表达。

Sales

销售

线索、需求诊断、跟进、客服与转人工。

发布会验收：真实工作场景、清晰岗位定义、可打开的网站、短视频、现场发布、人机边界，以及未来六个月能否真正运行。
