# 7 天 Action 行动转化包

行动单独成页。无论是否到场，都要用一个真实流程、一个可运行产物和一组证据完成行动验证。

## 未到场创始人行动转化包

> [!important] 这一部分的目标
> 让没有来现场的创始人不只是“补课”，而是在 **7 天内完成一个可验证的组织变化**。阅读笔记、看录像不算完成；只有交付证据、让真实工作流程发生变化，才算完成。


## 一、补课不按“听了多少”，而按“做成什么”验收

未到场创始人只需掌握本场的五个核心变化：

| 从 | 变成 | 最小验收证据 |
|---|---|---|
| 会议结束后靠人回忆 | 会议默认录音，Agent 生成纪要和待办 | 1 次真实会议的录音、纪要、Owner 和截止时间 |
| 数据只是存起来 | 先定义问题，再让 AI 挖掘 | 1 个已定义的经营问题 + 1 份 AI 分析结果 |
| 招聘只看简历 | 看作品、业务基础和驾驭 Agent 的能力 | 1 道 Agent 实操题 + 统一评分表 |
| 员工各自私聊 AI | 团队在真实工场景共用 Agent | 1 个群聊 Agent 试点 + 一段共同完成的工作 |
| 个人经验留在脑中 | 业务专家持续贡献到公司知识库 | 1 次专家经验提取 + 本人确认过的标准答案 |


## 二、7 天行动 Sprint

### Day 0｜选一个战场，不同时改造全公司

创始人先回答两个问题：

1. 我最希望 AI 介入、但目前没有跑通的核心工作是什么？
2. 从个人尝试走向团队落地，最卡在哪一步？

然后只选一个高频、有真实数据、7 天内能验证的场景。推荐优先级：

1. 会议纪要与待办；
2. 销售对话复盘；
3. 内容生产与审核；
4. 招聘筛选与面试；
5. 经营数据日报。

### Day 1｜建立基线

记录试点流程当前的真实数据：

- 每次需要多少人、多少时间？
- 一周发生多少次？
- 常见错误、返工、丢数据在哪里？
- 什么结果才算“好”？谁有资格判断？

> [!warning] 先写标准答案
> 如果没有业务专家给出标准答案，不得直接以 AI 输出为准。至少收集 3 个优秀样本和 3 个失败样本，让业务负责人写明判断标准。

### Day 2｜让上下文可被 Agent 读取

建立一个最小项目目录，只放本试点必需内容：

```text
00-试点目标
01-标准答案
02-优秀与失败样本
03-业务原始记录
04-Agent输出
05-人工复核与反馈
```

不要先建“公司大知识库”。先确保 Agent 知道到哪里找、找哪些文件、以什么标准输出。

### Day 3｜跑通第一次真实任务

不做 Demo，直接选一次真实业务：

- 由 AI 完成初稿或建议；
- 由业务专家判定正确/错误；
- 保留修改前后的对比；
- 把错误原因回流到规则、Skill 或知识库。

### Day 4｜从创始人个人使用变成 3 人共用

试点小组固定为三个角色：

| 角色 | 责任 |
|---|---|
| 创始人/高管 Sponsor | 定义目标、拆除阻力，不代替团队操作 |
| 业务 Owner | 提供标准答案，对 AI 结果负责 |
| AI Builder | 搭建和修改 Agent/Skill，记录失败原因 |

所有沟通放在一个共享群或项目区，不依赖创始人私聊中转。

### Day 5｜把一次成功变成可重复流程

固化四样东西：

1. 一条触发规则：什么时候启动；
2. 一份输入清单：必须给 AI 哪些上下文；
3. 一份输出模板：产物必须包含什么；
4. 一个人工闸门：哪类结果必须由谁批准。

### Day 6｜对比基线，不用感觉评价

| 维度 | 试点前 | 试点后 | 结论 |
|---|---:|---:|---|
| 人工耗时 |  |  |  |
| 完成周期 |  |  |  |
| 一次通过率 |  |  |  |
| 返工次数 |  |  |  |
| 关键数据留存率 |  |  |  |
| 业务 Owner 满意度（1–10） |  |  |  |

> [!tip] 本场课件的两个验收节点
> - **D3 · 8 月 15 日**：本人第一份产物是否出现？旧入口是否停用？Context、Owner 与验收标准是否写清？
> - **D7 · 8 月 19 日**：是否出现第二个人、第二次复用或一个真实业务信号？下一场私董会先复盘证据，不复述计划。

### Day 7｜发布试点战报并做下一个决定

三选一：

- **扩大**：数据有改善，扩到第二个小组；
- **继续打磨**：有价值但稳定性不足，再跑 7 天；
- **停止**：收益不成立，记录原因，换下一个场景。

## 四、俱乐部如何确保他们真正完成

### 1. 一位到场成员绑定一位未到场成员

到场成员不负责代做，只负责两次检查：

- Day 1：是否选了真实场景，有没有基线和 Owner；
- Day 7：是否有真实证据，而不是只有一份方案。

### 2. 群内只收“战报”，不收学习感想

战报固定为四句：

1. 我改的是哪个真实流程；
2. 什么数据变好了；
3. AI 犯了什么错；
4. 下一周是扩大、打磨还是停止。

### 3. 下次私董会不重新讲理论

开场直接复盘三类案例：

- 1 个已成功扩大的案例；
- 1 个仍在打磨的案例；
- 1 个果断停止的案例。

这样可以让成员明白：失败不是问题，没有真实试点和证据才是问题。


## 五、安全与组织边界

- 销售对话、微信、会议录音进入 AI 前，必须确认客户授权、员工知情、平台规则和数据安全；
- 不得用 AI 偷偷监控员工，要公开说明收集什么、用于什么、谁能看到；
- 不得因业务专家贡献经验就直接削弱其岗位，要同步设计新角色、绩效和收益；
- AI 输出涉及招聘、客户承诺、定价、投放、法务或人事决策时，必须保留人工审批。
