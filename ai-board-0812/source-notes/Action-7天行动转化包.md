# 现场讨论形成的 Action

这些不是会后额外设计的统一作业，而是 Vivian、亦仁和在场创始人在分享与讨论中明确提到、可以继续推进的动作。每位创始人根据自己的真实问题选一项，不要求全部执行。

## 一号位本人先改变

- **亲自下场一次**：创始人选择一个真实流程，从需求、构建、部署到复盘完整做一遍，不只批预算、听汇报。
- **只做一两个真问题**：从大量 AI 可能性中收缩到一两个高价值问题，持续迭代到足够深。
- **使用最好的模型和足够 Token**：探索期不因成本焦虑降低实验密度，同时记录失败和可复用成果。
- **建立个人 AI 工作台**：让会议、日程、任务、关键对话和决策逐步进入可调用的 Context。

**验收证据：** 一个可运行工具、工作台、Agent 记录、真实产物，或一次完整的前后对比。

## 把会议变成行动入口

- 选择一场真实会议，跑通“**录音 → 纪要 → Action → Owner → 截止时间 → 自动通知**”。
- 重要会议默认录音；会后保留可追溯原文，而不只留高度压缩的摘要。
- Agent 不只生成纪要，还要同步客户档案、公司记忆或内容产出。
- 会议中能直接完成的资料整理、方案草拟和任务创建，当场开始，不留到会后重新启动。

**验收证据：** 一场会议的录音、纪要、Action、Owner、截止时间和通知记录。

## 把 Context 变成组织资产

- 为公司知识库建立“**目录—摘要—原文**”三级索引，标明正式版本和引用范围。
- 把群聊、会议、文档、业务数据和老板反馈接进统一 Context；优先解决“沉睡数据”无法被调用的问题。
- 为一个核心负责人建立“**群聊/会议 → Daily Sync → 风险 → 决策**”工作台。
- 明确哪些信息可以读取、谁可以读取、为什么读取、保留多久；敏感数据保留权限边界。

**验收证据：** 第一版知识目录、正式版本入口、Daily Sync 结果及权限说明。

## 为业务建立标准答案

- 选择一个高频业务场景，由业务专家写出第一版判断标准和正确样本。
- 让 AI 执行一次，再由业务专家复核，记录错误类型而不是只说“不准确”。
- 为招聘、投放、定价、客户承诺、人事等高风险场景保留人工闸门。
- 把业务专家的反馈持续回流 Agent，使标准随业务变化迭代。

**验收证据：** 标准答案、输入清单、输出模板、一次 AI 结果及人工复核记录。

## 让 Agent 进入真实业务闭环

- 工程师或 Agent 直接面对用户：接收问题、构建、上线、回访、继续迭代。
- 给新产品一组真实内测用户，不让工具停在内部演示。
- 内容、直播、销售或运营场景只选一个 Loop，完成“输入—执行—反馈—复用”。
- 咨询与知识服务从“交课程、文档、资料”转向交付可直接使用的文章、视频、判断或业务结果。
- 不用 Token 数量代替业务结果，用效率、质量、收入、成本、体验或决策变化做验证。

**验收证据：** 真实用户反馈、Bug/需求记录、迭代版本，以及至少一次复用或业务信号。

## 推动全员进后端

- 选择一个非技术岗位，在 7 天内用 AI 交付一个可运行的小工具。
- 训练分三层：工具使用、前后端/API/数据库基础、十倍与并行构建思维。
- 通过内部黑客松围绕真实业务构建 Agent 或 Skill；优秀产物进入 Skill Hub 供全员复用。
- 先让少数尖兵跑通，再扩散到更多岗位，不把“全员培训”当成转型完成。

**验收证据：** 一个非技术岗位产物、使用说明、第二位同事的复用记录。

## 让团队围绕同一个 Agent 工作

- 试点一个团队共用 Agent，把工作从个人私聊迁移到群聊或共同 Thread。
- 推动 Work in Public：过程、错误、修正和反馈尽量进入公共上下文。
- 业务专家与 AI 人员长期共处，共同承担结果，而不是一次性交接需求。
- 建立员工离开后仍可继续使用的组织 Agent 资产和权限交接机制。

**验收证据：** 一个共用 Agent 群、共同完成的一段真实工作，以及 Context 更新记录。

## 把招聘、激励和人员机制一起改

- 把候选人的 Agent 实操加入招聘，用真实任务检验基础能力和驾驭 AI 的能力。
- 将面试官的负反馈回流筛选 Skill，持续修正 AI 简历评分。
- 为主动构建、真实复用和业务结果设计奖励、绩效与职业发展路径。
- 为贡献隐性知识的业务专家设计新岗位和未来价值，降低“交出经验就被替代”的恐惧。
- 老板先提供环境、工具与培训；对长期不行动、与新方向不匹配的人及时做决定。

**验收证据：** 一份真实任务、评分与反馈记录；一项新的奖励或岗位机制。

## 用两层行动卡承接

### 第一层｜一号位本人实验

1. 本人仍未真正接入 AI、却会影响企业的一项核心工作是什么？
2. 未来 7 天，本人亲自用 AI 重做哪个真实任务？
3. 第一份可被看见的产物或使用轨迹是什么？

### 第二层｜写进组织默认

1. 停止哪条旧做法或旧入口？
2. 团队从现在起形成什么新默认？
3. Owner 是谁，必须接通哪些 Context 与权限？
4. 7 天后用什么证据证明改变发生？

## 复盘节点

- **D3｜8 月 15 日**：本人第一份产物出现；旧入口是否停用；新入口是否生效。
- **D7｜8 月 19 日**：出现第二个人或第二次复用；基于证据决定继续、调整或停止。
- **90 天假设**：如果新默认成立，哪项经营指标会发生什么变化？

## 7 天后只交四样东西

- 一号位本人做了什么；
- 第一份可见产物或使用轨迹；
- 团队的新默认是否发生，谁完成了复用；
- 下一步是继续、调整，还是停止。
