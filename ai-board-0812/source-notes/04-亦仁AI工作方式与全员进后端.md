# 04-亦仁AI工作方式与全员进后端

亦仁分享创始人亲自下场、四台电脑、百亿 Token、超级助理、部门 Agent 与 AI 二次创业。

亦仁开场说明，过去两年团队和社群围绕 AI 做了大量实践，也踩过很多坑。本次 PPT 由 AI 基于他的完整上下文生成，他本人只快速看过一遍，因此分享本身也是一次“AI 带着创始人完成表达”的现场案例。

### 开场给出的分享框架

1. 创始人本人如何深度使用 AI；
2. 团队如何使用 AI，如何组织、考核和培养“尖兵”；
3. 这些实践背后的组织机制；
4. 如何把方法继续推进到更大范围。

### 亦仁与社群的背景数据（现场口述）

- 社群从 2017 年开始发展；
- 累计约 **8 万名付费会员**；
- 核心成员包括创作者、操盘手、电商、自媒体与 OPC 等互联网创业者；
- 当前每月在全国组织约 **300–400 场**线下交流；
- 过去主题以流量为主，现在已几乎全部聚焦 AI；
- 亦仁本人已经深入一线写代码、改 Bug，并与 Agent 一起工作；
- 团队内部运行的 Agent 数量据估计已达数百个；
- 团队每日 token 总消耗现场口述约 **100 亿**，其中 7–8 名 Agent 工程师由亦仁直接管理，并配置 Codex 与 Claude 高规格账号。


## AI 时代，老板不下场就没有好下场

亦仁给出的第一个判断非常直接：老板的认知决定公司的天花板，而 AI 工程能力会把这种差距进一步放大。同一种模型，在不同人手里创造的价值完全不同；如果老板、核心合伙人或操盘手无法成为公司里 AI 使用最深的几个人，组织的 AI 水平很难突破。

> 💎 “老板不下场，没有好下场。”

他认为，老板掌握 AI 工程能力后，价值至少可以从 10 倍起步；用得足够深入，出现百倍、千倍的放大也有可能。这里的“下场”不是偶尔与 ChatGPT 对话，而是亲自写、亲自搭、亲自改 Bug、亲自设计工作流，并持续面对失败结果。


## 亦仁个人使用 AI 的四个阶段

| 阶段 | 时间口径 | 工作方式 | 能力变化 |
|---|---|---|---|
| 对话阶段 | 去年为主 | 把 AI 当智囊，深度讨论问题 | 放大思考与判断 |
| 编程阶段 | 去年 9–10 月后 | 深入使用 Claude Code 等工具 | 从对话进入产品构建 |
| 快速产出阶段 | 今年 6–7 月 | Codex、Claude Code 深度使用 | 想法到第一版约 20 分钟 |
| Looper 阶段 | 今年 8 月起 | 设定目标，让 Agent 持续执行、反馈、再执行 | AI 不停机，工作进入循环 |

进入快速产出阶段后，技术门槛被显著降低，一个工作台、PPT 或产品可以在想法出现后的约 20 分钟内形成第一版。到 Looper 阶段，重点不再是单次完成，而是让 Agent 围绕目标持续工作。


## 四台电脑与百亿 Token：不是炫技，而是持续运行的基础设施

亦仁目前使用四台远程电脑，其中包括 MacBook Air、家中的 Mac mini、新加坡的 Mac mini，以及一台处理高挑战任务的高性能电脑。家中 Mac mini 长期登录微信、飞书，保存主知识库和核心数据；设备之间可通过 iCloud、云引擎和远程桌面协同。

使用强度：

- 亦仁个人日均约 **5–10 亿 token**，高峰超过 10 亿；
- 团队日均总消耗约 **100 亿 token**；
- 团队中约有 7–8 名直接管理的 Agent 工程师，配置 Codex 与 Claude 高规格账号；
- 内部运行的 Agent 据估计已有数百个；
- 社区排行榜头部用户，现场口述可达到日均 100 亿 token 以上。

这些数据用于说明使用强度，均为现场口述，不等同于经营绩效。真正需要追踪的是：这些投入是否转化为质量、效率、收入或成本变化。


## 从全员 AI 编程到“全员进后端”

公司从今年 3–4 月开始加速全组织使用 AI，6 月统一技术栈，以 Codex 为核心工作台，推动全员进入 AI 编程。之后又提出更激进的目标：**全员进后端**。

早期先由一支 Agent 工程师小分队跑通案例。他们中不少人并非传统技术背景，却已经可以独立开发产品、迭代产品、上线服务器和处理数据库。案例成立后，亦仁判断：非技术岗位同样能够进入后端，因此开始把这套能力推向全公司。

“全员进后端”并不是要求所有人转职程序员，而是要求业务人员不再只停留在提需求和使用界面，而能够直接构建、修改、部署自己需要的工作系统。


## 超级助理：把创始人的所有上下文汇成一个工作台

亦仁的核心工作台以 Claude Code 客户端为主。他搭建了一个“超级助理”项目，接入微信、飞书、Codex/Claude 的使用记录、公司内部系统及外部社交数据，并每日拉取增量。

信息进入后，会按既定模板沉淀为：

1. 创始人当天在微信、飞书、会议中的观点和承诺；
2. 组织激励、产业协同、机制、资金配置等核心主线；
3. 老板的任务台、待处理事项与风险；
4. 当日日程和未来 7 天安排；
5. 已完成、正在推进和答应别人但尚未完成的事项；
6. 可供团队调用的“AI 亦仁”与公司知识。

Daily Sync 每天约 8:30 开始运行。亦仁到公司时，系统已完成当天信息整理，他先看这份工作台，再判断今天需要亲自处理什么。


## 会议必须录音，因为没有上下文就无法管理

亦仁要求：与他沟通任何工作，必须打开飞书录音；同事之间的重要沟通也应录音；会后把飞书纪要私发给他或放入群聊。

> 💎 “没有会议纪要，我就没上下文，我就没法把这个推进来。”

有了完整上下文后，AI 可以先扫描负责人覆盖的部门、群聊、会议纪要和嵌套文档，整理各模块进度、遗漏与风险。负责人先在文档中批注，AI 再读取批注并继续对齐，原本需要长时间开会的管理动作，可以压缩为约 30 分钟，甚至无需再开会。

这里的关键不是“老板监控所有人”，而是建立公开的工作文化和明确权限。只要涉及隐私或敏感数据，就必须限制 Agent 可访问的群、文档和部门。


## 知识库不是一次搭好：框架与索引都要持续进化

飞书、微信和会议数据可以不全部复制到本地，但信息量变大后，必须建立结构化索引。亦仁把它比作图书馆：需要知道哪个区域、哪份目录、哪个主题下存放什么。

第一版框架可以按核心事件、部门、产品或议题建立；Daily Sync 跑入真实数据后，第二天就检查分类是否合理并快速调整。随着战略、组织和目标变化，索引也必须迭代。

### 权限原则

技术上的可访问不等于组织上的无限授权。正式落地必须明确：谁可读、为何读取、保留多久，以及哪些敏感信息不进入共享知识库。


## 部门 Agent：角色、上下文、权限必须分开

亦仁在飞书和本地服务器中创建了大量 Agent，包括组织部、财务、CEO 助理、研发、直播等不同角色。每个 Agent 需要分别定义：

- 职能：它负责什么问题；
- Skill：它用什么流程完成；
- Context：它应读取哪些知识；
- Permission：它可以访问哪些群、人员和数据；
- Delivery：结果发到哪里，由谁确认。

如果所有职能混在一个 Agent 中，上下文容易混乱。高频 Agent 会部署在云服务器持续运行，不依赖个人电脑是否合盖；知识库和常用文件可以由 Claude Code、Codex 等多个工作台共享。

亦仁还设置了一个每日公司信息助手：读取飞书信息后先检查风险与敏感数据，确认安全，再把整理后的上下文分享给全公司，避免团队在决策时缺少共同信息。


## 老板要从老业务抽身，带队完成一次 AI 二次创业

现场有人问：当执行越来越多交给 AI 后，老板每天究竟在做什么决策？亦仁把老板的工作分为两块：

1. **老业务迭代**：本质是 SOP 的 AI 化，逐步交给业务负责人决策，老板兜底；
2. **新业务重构**：用 AI 从 0 到 1 重新设计工作流，是一次组织的二次创业。

> 💎 “老的工作流迭代是线性的，只有重构工作流，才能带来新的增长和变化。”

老板如果仍然盯着老业务，就没有时间学习 AI，也无法打开新的增长空间。更合理的方式是让负责人承担老业务，允许其犯错；老板站到“10 倍、非线性”的视角，带一支蓝军重新思考产品、流程和组织。


## 直播 Agent：从实时提示到自动复盘

团队已经在直播场景部署 Agent：实时读取评论、订单和关键数据，在大屏上提示主播应该如何调整；直播结束后立即生成复盘，并在群内输出：

- 核心数据；
- 评论与用户信号；
- 目标是否达成、流量是否健康；
- 做得好的地方与问题；
- 下一步动作、负责人和数据来源。

这把“直播助理跟场—四小时后复盘”改造成“边播边指导—结束即复盘”。外部平台数据可通过官方 API、授权工具或合规的数据接口获得；不得把绕过平台规则的抓取方式默认为可用方案。


## 内容 Agent：先定义好内容，再逐步替代判断

在内部社区，亦仁先把自己对“好帖子、精华帖”的判断标准教给 Agent，让它按标准评选内容。进一步调教后，Agent 可以从建议是否加精，逐步走向直接执行。团队还搭建了外部内容数据看板，汇总抖音、小红书、公众号、视频号等平台数据，用于内容判断与复盘。

这里再次验证了本场前半段的共同结论：AI 自动化之前，必须先由业务专家明确标准答案。


## 投入原则：再穷不能穷模型，再省不能省 Token

亦仁对探索期的投入态度非常激进：能用最好的模型，就不先用次优模型；团队使用 AI 的成本全员报销，允许一半探索暂时没有结果。

> 💎 “再穷不能穷模型，再省不能省 Token。”
>
> 💎 “允许浪费，先激进。”

其逻辑是：探索早期的第一目标是扩大使用边界、发现新场景，而不是过早压缩成本。如果一开始就处处节省，团队尚未形成足够使用量，就很难找到真正的新工作流。等边界和模式逐步清晰，再开始优化模型、流程与成本。

但“允许浪费”不等于永远不核算。建议分为两个阶段：

| 阶段 | 目标 | 管理方式 |
|---|---|---|
| 探索期 | 增加使用密度、发现高价值场景 | 高额度、低审批、记录实验与失败 |
| 规模期 | 稳定质量并优化单位成本 | 模型分层、预算、成功率和 ROI 管理 |
## 有判断与审美的人，会被 AI 放大百倍

亦仁继续把“老板下场”推向更明确的组织判断：AI 不只是提高员工效率，而是在放大一号位已经拥有的判断、审美、产品经验和业务能力。与其继续投入大量精力优化招聘，不如先让老板学会构建 Agent，把最佳实践变成可复制的系统。

销售也是同一逻辑。过去企业依赖顶尖销售；当销售知识库、最佳实践和完整流程被沉淀为 Agent 后，普通销售甚至大学生也可能快速达到约七八十分。这里并非“不再需要人”，而是把招聘重点从寻找少数天才，转为用 Agent 抬高团队能力下限。

> 💎 “有判断、有审美的人，他的能力能放大一百倍。”

## Agent 工程师不是全栈，而是“从用户到用户”

亦仁把大部分老业务交给负责人，自己直接管理由原产研团队进化出的 Agent 工程师小队。第一批从约 10 人的产研团队中选出 4 人，背景包括前端、后端、产品和运营；要求他们在三个月内成为能独立完成开发、上线和迭代的全栈工程师。此后继续扩充，目前现场口述约有 10 人具备端到端开发能力。

但他重新定义了“端到端”：不是从前端走到后端，而是**从用户到用户**。

`用户提出需求 / Bug / 想法` → `工程师直接沟通` → `构建并上线产品` → `回到用户验证是否解决问题` → `继续迭代`

工程师不能只交付代码，还要完成用户反馈闭环。这正是 FDE 的核心：面向用户、端到端完成交付。

## 从全员进后端，到十倍全栈工程师

亦仁对组织提出两层要求：

1. **50 多人逐步进后端**：公司提供环境、资源与内部基建，让非技术岗位也能构建工具；
2. **约 10 名 Agent 工程师升级为十倍全栈工程师**：不再线性地一次解决一个问题，而要并行推进多个真实项目。

现场展示的 Token 看板被用作使用密度的粗略信号：有运营人员单日现场口述约 20 亿 Token，用于搭建从选题、对标、生产到发布的自媒体工作台；一位原产品经理单日约 10 亿 Token。亦仁强调，这些数字不能单独证明业务价值，但能暴露一个人是否真正进入高密度构建状态。

## 三层训练：工具、后端知识与十倍思维

全员转型不是发账号后自行摸索。亦仁介绍了三层内部训练：

| 层级 | 训练内容 | 目标 |
|---|---|---|
| 工具层 | Codex、飞书 CLI 及内部工具组合 | 员工能够在飞书工作现场调用 AI |
| 后端层 | 前端、后端、API、数据库等基础概念 | 非技术岗位真正“进后端” |
| 思维层 | 从线性解决问题转向并行、多项目、十倍视角 | 成为十倍工程师 |

训练之后，公司通过内部黑客松让员工围绕真实业务问题构建 Agent 和 Skill。优秀产物进入内部 Skill Hub，由全员复用，而不是停留在个人演示。

## 产品闭环的最后一公里：给工程师 200 个真实用户

亦仁认为，工程师只做出产品还不算闭环。产品如果没有真实反馈，会很快成为“死产品”；工程师也无法建立对用户和业务的判断。

他的做法是利用社区优势，为内部新产品快速组织约 200 人的内测群。用户持续反馈 Bug、需求和使用问题，工程师直接收集、判断、修复、上线并回访。老板的作用不是替工程师逐项决策，而是先帮他走完“连接用户”的最后一公里，直到工程师能自己转动飞轮。

## AI 推动机制：培训、黑客松、共享与真实奖惩

亦仁总结的组织扩散路径是：

`老板先跑通` → `核心工程师复刻` → `内部培训` → `黑客松产出` → `Skill Hub 共享` → `真实用户反馈` → `更多岗位扩散`

文化建设同样需要一号位带头。他在全员学习群里高频分享调研、框架和实践，鼓励员工组织内部培训；员工用 AI 解决佣金结算、数据处理等问题后，再把过程写成白皮书或教程。现场举例，一位运营完成了面向非技术人员的 AI 编程入门指南。

推动并不只有鼓励。亦仁现场直言，公司曾要求 P5 以上员工述职时汇报 AI 使用和成果，并对明显跟不上者做人员调整。这个动作让团队意识到转型不是口号。该做法属于其公司特定阶段的管理选择，其他组织不能脱离劳动合规、岗位标准和培养周期机械照搬。

## 真正的红利：老板亲自带、顶配账号与新职业路径

现阶段对 AI 用得好的人，亦仁认为最重要的激励有三类：

- 老板亲自带，进入最密集的真实问题现场；
- 配置高规格模型账号和充足 Token，不让成本焦虑阻断探索；
- 设计从内部 Agent 工程师走向企业服务者、独立操盘手的职业路径。

这不仅是技术培养，也是“人的未来”设计。员工看到能力升级后有更大的项目、市场和收入空间，才会愿意投入高强度学习。

## 最大的坑不是技术，而是注意力失控

AI 让可做的事、可解决的问题和可颠覆的流程突然增多，亦仁当前最大的反思是：每天开出太多新议题，却无法把任何一个做深。

> 💎 “可能性越多、机会越大的时候，越要专注到一两个点上，把它做透、做到极致。”

他观察到高 Token 排行靠前者往往已经找到一个真问题，并持续迭代到足够深；没有真问题的人，即使不断对话也难形成高价值结果。Token 密度必须绑定问题密度，而不是为了排行榜消耗。

## 与 AI 配合的原则：行有不得，反求诸己

现场有人提问：知识库和 SOP 已经建立，但 Agent 的回答越来越发散，应该如何迭代？亦仁的回答是，发散通常意味着人的约束、标准或任务定义不够清楚。

> 💎 “任何和 AI 配合的问题，如果我认为 AI 达不到我的要求和标准，那是我的问题。”

他的工作假设是：现有模型已能解决在场多数人的问题。若输出不达标，应先检查目标、标准、边界、样本和反馈是否定义清楚。这样问题才仍处于人的可调范围内，而不会轻易归因于“模型不行”。

## 上下文是公司的新资产，版本管理是资产治理

亦仁用一个生活例子解释上下文：如果 AI 同时知道日程、微信约定和真实意图，它能判断“周三体检”可能只是拒绝饭局的说法；如果只看到一句话，就无法理解真正安排。

企业上下文同样包括：

- 组织架构与人员职责；
- 群聊、会议、录音与任务；
- 老板的决策偏好和反复反馈；
- 项目历史、业务数据与最新版本；
- 在授权边界内的个人健康、家庭与自我探索资料。

随着上下文增多，版本治理变得关键。亦仁会区分过程资料与最终版，让 Agent 优先读取正式版本；历史记忆也要定期清理，删除过期、冲突或质量差的内容。否则“记得更多”反而会形成混乱记忆。

> 💎 “上下文是公司的新资产。”

## 组织转型像重新上大学，不能第一天就问工资

亦仁认为，从老板认知提升，到组织能力跟上，再到经营结果显现，需要真实的学习和迁移周期。不能刚开始训练团队，就立刻用最终业务结果否定过程。

> 💎 “你不能刚上大学就问他工资多少。”

他的阶段判断是：一年后再系统追问结果，当前先坚持做正确的事——老板使用 AI、团队使用 AI、重构思维和流程。同时仍应保留过程证据，避免“长期主义”成为不验收的借口。

## 从人访问内容，到 AI 访问内容

亦仁把生财有术过去十年的知识库开放给会员使用，并现场口述将多年累计的大量内容通过 MCP 提供给用户的 AI 直接访问。产品逻辑因此发生变化：过去是人进入平台搜索和阅读，未来是 Agent 调用社区内容、项目和 Skill 后直接帮助用户解决问题。

Skill Hub 则希望让社区成员共享内容创作、运营管理等技能，现场预计后续将汇集数千条 Skill。该数量和上线时间均为现场计划，不写成已完成结果。

## 生财有术产品演示：内容、项目、训练与连接

约 `03:29:31` 后，讨论从组织方法转为生财有术产品介绍。亦仁现场说明其主要采用年费订阅制，口述价格约 3,300 元/年。会员价值被拆为几类：

1. **内容**：社区成员分享的创业、AI、出海、电商与内容平台经验；
2. **项目**：团队从大量信息中筛选、结构化可尝试的赚钱方向，说明为什么值得做、如何赚钱和具体步骤；
3. **训练**：以航海/训练营形式提供任务、社群和课程，主题包括视频带货、AI 产品、海外产品、知识库和 AI 视频；
4. **聚会与连接**：大量线下聚会、资源库、人才链接与未来可能的任务接单；
5. **AI 访问**：借助搜索助手和 MCP，让会员在自己的 Agent 工具中调用社区知识。

现场举例，8 月 5 日开始的一期 21 天训练营口述有 6,000 多人报名，由社区成员担任老师并用积分等方式激励；平台每月口述有数百场聚会。以上经营数字与产品功能均来自现场演示，未做外部核验。

亦仁随后补充，社区除基础会员外，还存在面向垂直学习的产品层级。现场提到“航海家”与“深海圈”等名称，其中航海家围绕 AI 编程、AI 视频、B 站带货等方向进行更深入训练；现场口述年费区间约 5,000–10,000 元。由于产品名称、层级关系和价格均来自即席问答，本轮只记录口述，不作为正式产品说明。

这一段的组织意义不只是“介绍公司卖什么”，而是展示社区如何形成飞轮：

`团队筛选项目` → `成员学习和实践` → `成员分享结果与方法` → `平台结构化沉淀` → `更多人和 Agent 调用` → `形成新的项目、人才和服务连接`


## 航海家：面向老板的 AI 学习与连接场

亦仁进一步介绍，基础社区之外还有更面向老板的产品。航海家通过老板群、线下大课、企业游学和成员交流，把不同领域的一号位连接起来；现场口述一年约组织四次大课。课程案例包括 AI Native IP、短视频与直播自动化、AI 知识库和电商内容流水线等。

这里的价值不是让老板学完所有技术，而是持续看见真实案例、找到可以合作的人，并把一个具体问题带回公司推进。

## MCP：让社区知识直接进入用户的 Agent

现场演示了把生财有术知识库接入 Codex、Claude 等工作台的过程。会员复制授权信息并完成配置后，可以直接在自己的 Agent 中提问，不必先进入网站逐页搜索。

例如，用户可以询问小红书电商、视频制作或推广计划。Agent 会检索社区内部内容，给出回答，并保留信息来源，用户仍可回到原文判断可靠性。

这意味着知识产品的交付方式正在变化：

`用户进入网站找内容` → `Agent 调用社区知识` → `结合用户问题生成答案` → `回链原始信息源`

关键不是给模型增加一个搜索框，而是把高质量、可追溯的私域知识变成 Agent 可以调用的上下文。

## 咨询产品从“交资料”转向“交结果”

亦仁判断，偏咨询和知识服务的公司都会重新设计交付方式。过去交付课程、文档和资料；未来应尽量直接交付可使用的结果。例如，不只教用户如何做自媒体，而是帮助生成可以发布的文章和视频。

> 💎 “之前我们交付知识、课程、文档资料，现在应该直接交付结果。”

这种转型初期一定会出现 Bug、浪费和冗余。亦仁认为，在探索阶段过早追求秩序、清晰和低成本并不现实；团队需要先在混乱中找到真正有效的新路径。

## AI 门槛会下降，最终壁垒仍是信任与品牌

亦仁最后把组织方向收束到 FDE：当团队成员都能从用户问题出发，调用 AI 完成构建并回到用户验证，个人能力和价值会被放大，组织也可能把这套能力对外输出。

但他判断，AI 工程能力的门槛会继续下降，大多数人最终都能跨越。真正长期稀缺的，仍然是：

- 对人的理解；
- 判断与审美；
- 用户信任；
- 品牌积累；
- 老板多年形成的行业经验。

> 💎 “最核心的不是技术，最后还是信任和品牌。”

所以这不是年轻技术人才单方面替代老一代的时代，也可能是有经验的一号位重新创业的时代：补上 AI 能力，再把已有价值放大十倍、百倍。

## AI 转型中的人员选择：先给环境，也要及时结束不匹配

现场有创始人追问：传统企业推进 AI 转型时，如何处理不愿意改变、跟不上新工作方式的员工？亦仁给出的原则分为两层：

- **老板先尽责**：提供学习环境、工具资源和培训机会，不能只下命令、不提供条件；
- **对长期不匹配的人及时做决定**：当成员已经没有成长意愿，也跟不上团队方向时，结束合作可能比长期消耗对双方更负责。

> 💎 “不合适的人及时结束，其实是对双方的负责。”

勉强把人留在原岗位，既会让组织持续内耗，也可能让个人错过重新学习、转岗甚至创业的机会。管理者需要把期待、机会和边界提前说清楚，再基于真实行动做人员判断。
