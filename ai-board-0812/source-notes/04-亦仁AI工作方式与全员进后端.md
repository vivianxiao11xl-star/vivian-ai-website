# 04-亦仁AI工作方式与全员进后端

亦仁分享创始人亲自下场、四台电脑、百亿 Token、超级助理、部门 Agent 与 AI 二次创业。

亦仁开场说明，过去两年团队和社群围绕 AI 做了大量实践，也踩过很多坑。本次 PPT 由 AI 基于他的完整上下文生成，他本人只快速看过一遍，因此分享本身也是一次“AI 带着创始人完成表达”的现场案例。

### 开场给出的分享框架

1. 创始人本人如何深度使用 AI；
2. 团队如何使用 AI，如何组织、考核和培养“尖兵”；
3. 这些实践背后的组织机制；
4. 如何把方法继续推进到更大范围。

### 亦仁与社群的背景数据（现场口述）

- 社群从 2017 年开始发展；
- 累计约 **8 万名付费会员**；
- 核心成员包括创作者、操盘手、电商、自媒体与 OPC 等互联网创业者；
- 当前每月在全国组织约 **300–400 场**线下交流；
- 过去主题以流量为主，现在已几乎全部聚焦 AI；
- 亦仁本人已经深入一线写代码、改 Bug，并与 Agent 一起工作；
- 团队内部运行的 Agent 数量据估计已达数百个；
- 团队每日 token 总消耗现场口述约 **100 亿**，其中 7–8 名 Agent 工程师由亦仁直接管理，并配置 Codex 与 Claude 高规格账号。


## AI 时代，老板不下场就没有好下场

亦仁给出的第一个判断非常直接：老板的认知决定公司的天花板，而 AI 工程能力会把这种差距进一步放大。同一种模型，在不同人手里创造的价值完全不同；如果老板、核心合伙人或操盘手无法成为公司里 AI 使用最深的几个人，组织的 AI 水平很难突破。

> 💎 “老板不下场，没有好下场。”

他认为，老板掌握 AI 工程能力后，价值至少可以从 10 倍起步；用得足够深入，出现百倍、千倍的放大也有可能。这里的“下场”不是偶尔与 ChatGPT 对话，而是亲自写、亲自搭、亲自改 Bug、亲自设计工作流，并持续面对失败结果。


## 亦仁个人使用 AI 的四个阶段

| 阶段 | 时间口径 | 工作方式 | 能力变化 |
|---|---|---|---|
| 对话阶段 | 去年为主 | 把 AI 当智囊，深度讨论问题 | 放大思考与判断 |
| 编程阶段 | 去年 9–10 月后 | 深入使用 Claude Code 等工具 | 从对话进入产品构建 |
| 快速产出阶段 | 今年 6–7 月 | Codex、Claude Code 深度使用 | 想法到第一版约 20 分钟 |
| Looper 阶段 | 今年 8 月起 | 设定目标，让 Agent 持续执行、反馈、再执行 | AI 不停机，工作进入循环 |

进入快速产出阶段后，技术门槛被显著降低，一个工作台、PPT 或产品可以在想法出现后的约 20 分钟内形成第一版。到 Looper 阶段，重点不再是单次完成，而是让 Agent 围绕目标持续工作。


## 四台电脑与百亿 Token：不是炫技，而是持续运行的基础设施

亦仁目前使用四台远程电脑，其中包括 MacBook Air、家中的 Mac mini、新加坡的 Mac mini，以及一台处理高挑战任务的高性能电脑。家中 Mac mini 长期登录微信、飞书，保存主知识库和核心数据；设备之间可通过 iCloud、云引擎和远程桌面协同。

使用强度：

- 亦仁个人日均约 **5–10 亿 token**，高峰超过 10 亿；
- 团队日均总消耗约 **100 亿 token**；
- 团队中约有 7–8 名直接管理的 Agent 工程师，配置 Codex 与 Claude 高规格账号；
- 内部运行的 Agent 据估计已有数百个；
- 社区排行榜头部用户，现场口述可达到日均 100 亿 token 以上。

这些数据用于说明使用强度，均为现场口述，不等同于经营绩效。真正需要追踪的是：这些投入是否转化为质量、效率、收入或成本变化。


## 从全员 AI 编程到“全员进后端”

公司从今年 3–4 月开始加速全组织使用 AI，6 月统一技术栈，以 Codex 为核心工作台，推动全员进入 AI 编程。之后又提出更激进的目标：**全员进后端**。

早期先由一支 Agent 工程师小分队跑通案例。他们中不少人并非传统技术背景，却已经可以独立开发产品、迭代产品、上线服务器和处理数据库。案例成立后，亦仁判断：非技术岗位同样能够进入后端，因此开始把这套能力推向全公司。

“全员进后端”并不是要求所有人转职程序员，而是要求业务人员不再只停留在提需求和使用界面，而能够直接构建、修改、部署自己需要的工作系统。


## 超级助理：把创始人的所有上下文汇成一个工作台

亦仁的核心工作台以 Claude Code 客户端为主。他搭建了一个“超级助理”项目，接入微信、飞书、Codex/Claude 的使用记录、公司内部系统及外部社交数据，并每日拉取增量。

信息进入后，会按既定模板沉淀为：

1. 创始人当天在微信、飞书、会议中的观点和承诺；
2. 组织激励、产业协同、机制、资金配置等核心主线；
3. 老板的任务台、待处理事项与风险；
4. 当日日程和未来 7 天安排；
5. 已完成、正在推进和答应别人但尚未完成的事项；
6. 可供团队调用的“AI 亦仁”与公司知识。

Daily Sync 每天约 8:30 开始运行。亦仁到公司时，系统已完成当天信息整理，他先看这份工作台，再判断今天需要亲自处理什么。


## 会议必须录音，因为没有上下文就无法管理

亦仁要求：与他沟通任何工作，必须打开飞书录音；同事之间的重要沟通也应录音；会后把飞书纪要私发给他或放入群聊。

> 💎 “没有会议纪要，我就没上下文，我就没法把这个推进来。”

有了完整上下文后，AI 可以先扫描负责人覆盖的部门、群聊、会议纪要和嵌套文档，整理各模块进度、遗漏与风险。负责人先在文档中批注，AI 再读取批注并继续对齐，原本需要长时间开会的管理动作，可以压缩为约 30 分钟，甚至无需再开会。

这里的关键不是“老板监控所有人”，而是建立公开的工作文化和明确权限。只要涉及隐私或敏感数据，就必须限制 Agent 可访问的群、文档和部门。


## 知识库不是一次搭好：框架与索引都要持续进化

飞书、微信和会议数据可以不全部复制到本地，但信息量变大后，必须建立结构化索引。亦仁把它比作图书馆：需要知道哪个区域、哪份目录、哪个主题下存放什么。

第一版框架可以按核心事件、部门、产品或议题建立；Daily Sync 跑入真实数据后，第二天就检查分类是否合理并快速调整。随着战略、组织和目标变化，索引也必须迭代。

### 权限原则

技术上的可访问不等于组织上的无限授权。正式落地必须明确：谁可读、为何读取、保留多久，以及哪些敏感信息不进入共享知识库。


## 部门 Agent：角色、上下文、权限必须分开

亦仁在飞书和本地服务器中创建了大量 Agent，包括组织部、财务、CEO 助理、研发、直播等不同角色。每个 Agent 需要分别定义：

- 职能：它负责什么问题；
- Skill：它用什么流程完成；
- Context：它应读取哪些知识；
- Permission：它可以访问哪些群、人员和数据；
- Delivery：结果发到哪里，由谁确认。

如果所有职能混在一个 Agent 中，上下文容易混乱。高频 Agent 会部署在云服务器持续运行，不依赖个人电脑是否合盖；知识库和常用文件可以由 Claude Code、Codex 等多个工作台共享。

亦仁还设置了一个每日公司信息助手：读取飞书信息后先检查风险与敏感数据，确认安全，再把整理后的上下文分享给全公司，避免团队在决策时缺少共同信息。


## 老板要从老业务抽身，带队完成一次 AI 二次创业

现场有人问：当执行越来越多交给 AI 后，老板每天究竟在做什么决策？亦仁把老板的工作分为两块：

1. **老业务迭代**：本质是 SOP 的 AI 化，逐步交给业务负责人决策，老板兜底；
2. **新业务重构**：用 AI 从 0 到 1 重新设计工作流，是一次组织的二次创业。

> 💎 “老的工作流迭代是线性的，只有重构工作流，才能带来新的增长和变化。”

老板如果仍然盯着老业务，就没有时间学习 AI，也无法打开新的增长空间。更合理的方式是让负责人承担老业务，允许其犯错；老板站到“10 倍、非线性”的视角，带一支蓝军重新思考产品、流程和组织。


## 直播 Agent：从实时提示到自动复盘

团队已经在直播场景部署 Agent：实时读取评论、订单和关键数据，在大屏上提示主播应该如何调整；直播结束后立即生成复盘，并在群内输出：

- 核心数据；
- 评论与用户信号；
- 目标是否达成、流量是否健康；
- 做得好的地方与问题；
- 下一步动作、负责人和数据来源。

这把“直播助理跟场—四小时后复盘”改造成“边播边指导—结束即复盘”。外部平台数据可通过官方 API、授权工具或合规的数据接口获得；不得把绕过平台规则的抓取方式默认为可用方案。


## 内容 Agent：先定义好内容，再逐步替代判断

在内部社区，亦仁先把自己对“好帖子、精华帖”的判断标准教给 Agent，让它按标准评选内容。进一步调教后，Agent 可以从建议是否加精，逐步走向直接执行。团队还搭建了外部内容数据看板，汇总抖音、小红书、公众号、视频号等平台数据，用于内容判断与复盘。

这里再次验证了本场前半段的共同结论：AI 自动化之前，必须先由业务专家明确标准答案。


## 投入原则：再穷不能穷模型，再省不能省 Token

亦仁对探索期的投入态度非常激进：能用最好的模型，就不先用次优模型；团队使用 AI 的成本全员报销，允许一半探索暂时没有结果。

> 💎 “再穷不能穷模型，再省不能省 Token。”
>
> 💎 “允许浪费，先激进。”

其逻辑是：探索早期的第一目标是扩大使用边界、发现新场景，而不是过早压缩成本。如果一开始就处处节省，团队尚未形成足够使用量，就很难找到真正的新工作流。等边界和模式逐步清晰，再开始优化模型、流程与成本。

但“允许浪费”不等于永远不核算。建议分为两个阶段：

| 阶段 | 目标 | 管理方式 |
|---|---|---|
| 探索期 | 增加使用密度、发现高价值场景 | 高额度、低审批、记录实验与失败 |
| 规模期 | 稳定质量并优化单位成本 | 模型分层、预算、成功率和 ROI 管理 |
